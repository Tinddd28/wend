# wend

> **In English:** wend is an interactive disk usage analyzer for the
> terminal — a directory tree with shares and sizes next to a sunburst or
> treemap chart, drawn with character cells. It ships as a single static
> binary with no dependencies. Full documentation:
> **[README.en.md](README.en.md)**. Note that the application interface
> itself is currently in Russian only.

*[English version](README.en.md)*

Интерактивный анализатор занятого места на диске для терминала.

Сканирует директорию в фоне и сразу показывает дерево с долями и размерами,
а справа рисует то же самое кольцевой диаграммой (sunburst) или treemap —
без графической оболочки, прямо в терминале.

## Возможности

- **Инкрементальный скан.** Дерево наполняется по мере обхода — не нужно
  ждать завершения, чтобы начать смотреть.
- **Четыре режима отображения:** список, горизонтальные полосы, кольцевая
  диаграмма и treemap. Диаграммы рисуются символами с цветным фоном и
  учитывают, что ячейка терминала вдвое выше своей ширины.
- **Связанные панели.** Ветка под курсором в таблице подсвечена на
  диаграмме, остальное приглушено.
- **Настоящие данные ФС:** доля от родителя, число вложенных элементов,
  время изменения, inode, число жёстких ссылок и реально занятое на диске
  место.
- **Дедупликация жёстких ссылок** по inode — файл, на который ведёт
  несколько ссылок, считается один раз.
- **Адаптивная вёрстка.** Колонки отключаются по мере сужения терминала,
  ничего не переносится и не разъезжается.

## Установка

Бинарь статический и не тянет за собой ничего: ни libc, ни рантайма. Он
работает и в дистрибутиве на musl, и в контейнере `FROM scratch`. Достаточно
положить один файл в `PATH`.

### Одной командой

```sh
curl -fsSL https://raw.githubusercontent.com/Tinddd28/wend/main/scripts/install.sh | sh
```

Скрипт определит ОС и архитектуру, скачает последний релиз, **сверит
контрольную сумму** и положит бинарь в `/usr/local/bin` (при необходимости
через `sudo`).

Полезные переменные:

```sh
PREFIX=$HOME/.local/bin sh install.sh   # установить без sudo
VERSION=nightly         sh install.sh   # свежая сборка из main
VERSION=v1.0.0          sh install.sh   # конкретная версия
sh install.sh --dry-run                 # посмотреть, что будет скачано
```

Если не хочется выполнять скачанный скрипт не глядя — а это разумно —
скачайте его отдельно, прочитайте и запустите:

```sh
curl -fsSLO https://raw.githubusercontent.com/Tinddd28/wend/main/scripts/install.sh
less install.sh && sh install.sh
```

### Скачать готовый бинарь

На странице [Releases](https://github.com/Tinddd28/wend/releases) рядом с
архивами лежат **распакованные бинари** — их можно скачать и запустить сразу,
без распаковки. Имя вида `wend_<ос>_<архитектура>`, версии в нём намеренно
нет: только так работает постоянная ссылка на «последний релиз».

```sh
curl -fsSLO https://github.com/Tinddd28/wend/releases/latest/download/wend_linux_amd64
chmod +x wend_linux_amd64
./wend_linux_amd64 ~/Downloads
```

### Скачать архив

Архив втрое меньше и несёт с собой `LICENSE` и `README`:

```sh
tar -xzf wend_v1.0.0_linux_amd64.tar.gz
sha256sum -c SHA256SUMS --ignore-missing   # SHA256SUMS лежит рядом с архивами
sudo install -m 0755 wend /usr/local/bin/wend
```

Под Windows архивы в формате `.zip`, бинарь внутри — `wend.exe`.

### Сборки без ожидания релиза

- **`nightly`** — свежая сборка каждого коммита в `main`, по постоянным
  ссылкам вида
  `https://github.com/Tinddd28/wend/releases/download/nightly/wend_linux_amd64`.
  Тег переезжает на каждый коммит, это канал «последняя сборка», а не
  история версий.
- **Артефакты CI** — на странице любого прогона
  [Actions](https://github.com/Tinddd28/wend/actions) внизу лежат готовые
  бинари под все шесть платформ, в том числе для пул-реквестов. Хранятся 30
  дней, доступны авторизованным пользователям GitHub.

### go install

```sh
go install github.com/Tinddd28/wend/cmd/wend@latest
```

Бинарь попадёт в `$(go env GOPATH)/bin` — убедитесь, что этот каталог есть
в `PATH`.

### Из исходников

Требуется Go 1.26.5 или новее (версия зафиксирована в `go.mod`).

```sh
git clone https://github.com/Tinddd28/wend.git
cd wend
go build -o wend ./cmd/wend
```

## Запуск

```sh
wend               # текущая директория
wend ~/Downloads   # конкретный путь
wend --version
wend --help
```

Недоступные из-за прав каталоги пропускаются, обход остального дерева
не прерывается.

## Управление

| Клавиши | Действие |
| --- | --- |
| `j` / `k`, `↓` / `↑` | вверх-вниз |
| `g` / `G`, `Home` / `End` | в начало / в конец |
| `Ctrl+f` / `Ctrl+b`, `PgDn` / `PgUp` | страница вниз / вверх |
| `l`, `→`, `Enter` | раскрыть директорию, шагнуть внутрь |
| `h`, `←` | свернуть директорию, подняться к родителю |
| `Tab` | переключить панель |
| `v` | сменить режим главной панели |
| `r` | пересканировать заново |
| `q`, `Ctrl+c` | выход |

## Режимы главной панели

Переключаются по `v` по кругу:

1. **Список** — размер, доля от объёма родителя, число вложенных элементов,
   имя.
2. **Полосы** — то же плюс горизонтальная гистограмма, отмасштабированная
   по крупнейшему соседу.
3. **Кольца** — sunburst: центр показывает суммарный объём, каждое
   следующее кольцо соответствует уровню вложенности, угол сегмента
   пропорционален размеру. До пяти колец; тон берётся из углового
   положения сегмента, поэтому вложенные элементы сохраняют цвет родителя.
4. **Treemap** — squarified-раскладка: площадь плитки пропорциональна
   размеру, до трёх уровней вложенности с подписями.

## Как читать цифры

Несколько мест, где `wend` намеренно расходится с наивным подсчётом:

- **Доля** считается от объёма **родителя**, а не всего дерева, — так она
  остаётся информативной на любой глубине.
- **Жёсткие ссылки.** Файл с `nlink > 1` учитывается в суммах один раз, по
  первой встреченной ссылке. Повторы помечаются `⇥`, показываются с нулевым
  вкладом, а их общее число видно в статусбаре. Именно поэтому итог может
  быть меньше, чем сумма размеров всех файлов.
- **Размер на диске** (`blocks × 512`) показывается в строке деталей, когда
  расходится с логическим размером больше чем на 10% — это бывает у
  sparse-файлов и из-за округления до размера блока. На платформах без
  `syscall.Stat_t` (Windows) inode, число ссылок и размер на диске
  недоступны, и дедупликация не выполняется.
- **Символические ссылки** не раскрываются: обход по ним не идёт, поэтому
  цикл через симлинк не может увести скан в бесконечность.

## Разработка

```sh
go test ./...          # тесты
go test -race ./...    # с детектором гонок: дерево читается из UI
                       # и пишется из горутины сканера
go vet ./...
gofmt -l ./cmd ./internal
```

Структура:

```
cmd/wend/              точка входа, разбор аргументов
internal/scan/         обход ФС и потокобезопасное дерево результатов
internal/humanize/     форматирование размеров, счётчиков и дат
internal/tui/          bubbletea-модель, layout, клавиши
  ├── sidebar/         таблица дерева
  ├── mainview/        главная панель и её режимы
  ├── statusbar/       детали выбранного объекта и подсказки
  ├── canvas/          растровый холст из символьных ячеек
  ├── chart/           кольцевая диаграмма и treemap
  └── style/           палитра и обрезка строк по ширине
```

## Сборка и публикация

Три workflow, все на официальных экшенах и `gh` CLI, без сторонних зависимостей:

| Workflow | Когда | Что делает |
| --- | --- | --- |
| [`ci.yml`](.github/workflows/ci.yml) | push в `main`, пул-реквесты | gofmt, `go vet`, `go test -race`, сборка под 6 платформ с выгрузкой артефактов |
| [`nightly.yml`](.github/workflows/nightly.yml) | push в `main` | тесты и обновление предрелиза `nightly` — свежая сборка по постоянной ссылке |
| [`release.yml`](.github/workflows/release.yml) | тег `v*` | проверки, тесты, архивы с `SHA256SUMS`, GitHub Release со списком изменений |

Выпустить релиз:

```sh
git tag -a v1.0.0 -m "v1.0.0"
git push origin v1.0.0
```

Теги с дефисом (`v1.0.0-rc1`) помечаются предрелизными и не подменяют собой
«последнюю версию».

Те же артефакты собираются локально, без ожидания CI:

```sh
./scripts/build-release.sh v1.0.0   # результат в dist/
```

Версия Go во всех workflow берётся из `go.mod`, чтобы CI не разъезжался с
проектом. Сборка всегда идёт с `CGO_ENABLED=0` и `-trimpath` — отсюда
статический бинарь и воспроизводимость.
